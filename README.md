# SinCombo

Приложение для строки меню macOS: Wi-Fi, Bluetooth, звук, календарь, VPN, аккумулятор и подписки на нейросети в одной панели. Состав и порядок блоков настраиваются.

ТЗ: https://claude.ai/artifact/NXm1VTgZQY1WkDVj5vpmPg · прототип: https://claude.ai/artifact/D7xgRm5Pjp8XcPP92Vu7gU

## Модули

| Модуль | Что делает | Реализация |
| --- | --- | --- |
| Календарь | Сетка месяца, события из системной базы календарей, создание событий | EventKit |
| Звук | Громкость, выключение звука, устройства вывода и ввода | CoreAudio |
| Wi-Fi | Питание, текущая сеть, подключение к сети | CoreWLAN, CoreLocation |
| Bluetooth | Питание, сопряжённые устройства, заряд | IOBluetooth, `system_profiler` |
| VPN | Переключатели системных VPN, время и трафик | `scutil --nc`, код из SinVpn |
| Аккумулятор | Заряд, источник питания, время, состояние | IOKit |
| Подписки | Лимиты и расход по подпискам на нейросети, баланс DeepSeek, даты продления | запросы к сервисам, связка ключей |

## Требования

- Mac на Apple Silicon, macOS 14 или новее.

## Установка

1. Скачайте `SinCombo.zip` со страницы [релизов](https://github.com/claudesiniakov/sincombo/releases) и распакуйте.
2. Перенесите `SinCombo.app` в «Программы».
3. Сборка подписана ad-hoc (без Developer ID): при первом запуске откройте «Системные настройки → Конфиденциальность и безопасность» и нажмите «Всё равно открыть».

Приложение запрашивает доступ к календарям, геолокации (без неё macOS не отдаёт имена сетей Wi-Fi) и Bluetooth — каждый только при первом обращении к своему модулю. У ad-hoc сборки разрешения привязаны к конкретной подписи, поэтому после обновления macOS может спросить их заново; с постоянным сертификатом (ниже) они переживают обновления.

## Подпись и обновления

Релизы подписаны ad-hoc: стабильной подписи нет, и TCC может спрашивать разрешения после каждого обновления. Чтобы этого избежать, достаточно самоподписанного сертификата «Сертификат кода»:

1. В «Связке ключей» → «Ассистент сертификатов» → «Создать сертификат…» сделайте сертификат с именем `SinCombo Signing` и типом «Код».
2. Экспортируйте его вместе с ключом в `.p12`.
3. Добавьте в секреты репозитория `SIGNING_P12` (p12 в base64) и `SIGNING_PASSWORD`.

CI импортирует сертификат во временную связку и подпишет им сборку; без секретов подпись остаётся ad-hoc, и ничего не ломается.

Обновление принимается, только если оно подписано **тем же** сертификатом, что и установленное приложение: отпечаток листового сертификата берётся из подписи работающей копии (`SigningIdentity` в Core) и передаётся в `codesign -R`. Компрометация GitHub-аккаунта или релизного токена не даст подсунуть чужой архив — он будет подписан другим сертификатом. Пока сборки ad-hoc, привязывать нечего: проверяются SHA256 архива, идентификатор бандла, версия и целостность подписи.

Смена сертификата: выпустите переходную версию, добавьте старый и новый отпечатки в `SigningIdentity.extraLeafHashes`, затем уберите старый.

## Сборка

На сервере разработки Swift нет: сборка и тесты идут в GitHub Actions (`.github/workflows/ci.yml`). Тег `vX.Y.Z` публикует релиз.

- `Sources/SinComboCore` — логика без интерфейса, покрыта тестами.
- `Sources/SinCombo` — приложение.
- `scripts/build-app.sh` — собирает `SinCombo.app` и архив; `SIGN_IDENTITY` и `SIGNING_KEYCHAIN` задают сертификат подписи, без них — ad-hoc.
